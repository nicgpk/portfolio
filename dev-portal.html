The Problem

Agoda's internal developer platform was fragmented, slow, and unscored. Creating a service took 1–2 working days; deploying to private cloud meant Slack and tribal knowledge. Home was a flat link dump with no SUS baseline — engineers couldn't find critical paths, and leadership couldn't measure whether design helped. As the first designer in DevOps, I had to name the pain before we could score it.

The broken service creation flow

Process

Domain immersion

Interviewed 15+ developers. Learned Kubernetes, Docker, and CI/CD to earn technical credibility.

Heuristic evaluation

Scored the platform against Nielsen's heuristics. Documented 47 usability issues.

Baseline & measure

Established SUS baseline (61.9). Re-ran every 2 quarters to track improvement.

Ideation & phased delivery

Phase 1: quick wins to unblock developers. Phase 2: full automation with approval workflows.

Goals

Three commitments that shaped the work — each tied to the surfaces we shipped.

01

Improve developer experience with measurable UX metrics

Replace a flat link dump with task domains and a searchable catalog — structure people can learn, and that SUS can track.

Service creation as a path

Same six beats — toggle to watch the maze become a guided path.

    02

    Migrate from servers to private cloud via UI

    Give developers a productized deploy path — environment, canary across DCs, review — and a clear way to move every legacy service off servers onto private cloud.

    03

    Restructure information so the important work surfaces

    Rebuild IA so developers see what matters first — clear hierarchy, less noise, and the critical paths easy to find.
